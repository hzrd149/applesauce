## Goal Achievement

The historical-key premise is disproved correctly: focused integration tests traverse the real community and private-channel history paths and decrypt old and new ciphertext using per-file imeta material. A syntactically hexadecimal but cryptographically unsupported nonce length is exposed as valid `encryption`, contradicting the phase's safe-diagnostic outcome. This is a blocker, not merely an advisory quality issue.

### Gaps Summary

One root gap blocks the goal: nonce validation checks only hexadecimal syntax, while Concord's public contract documents a 16-byte nonce and the runtime rejects short IVs. The existing passing parser suite is misleading on this boundary because its sole invalid-nonce case uses non-hex text. Later milestone phases address other Concord rotation and release concerns, not media nonce validation, so this gap is not deferred.
