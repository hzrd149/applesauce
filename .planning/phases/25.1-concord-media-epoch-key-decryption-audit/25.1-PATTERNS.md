## Shared Patterns

### Exact Wire Emission

**Source:** `packages/concord/src/operations/channel.ts` lines 64-77  
**Apply to:** operation, factory, and both integration tests

The writer appends the three fields after the base `imeta` entries in algorithm/key/nonce order. Treat this implementation and its exact-array regression assertions as immutable compatibility oracles.

### Safe Native Error Hierarchy

**Source:** `packages/concord/src/client/community.ts` lines 184-199  
**Apply to:** `helpers/imeta.ts` and parser tests

Use package-local native `Error` subclasses, public readonly context, and stable `name`. Error messages identify fields but never contain field values; raw metadata remains a separate attachment property.

### Real Cryptographic Oracle

**Source pattern:** existing Noble byte codecs in `private-channel.test.ts` line 15 and `community.test.ts` line 16  
**Apply to:** both epoch integration tests

Convert parsed hex via `hexToBytes`, import the 32-byte key with `crypto.subtle.importKey("raw", ..., "AES-GCM", false, ["decrypt"])`, and decrypt with the parsed nonce as `iv`. Test both successful plaintext recovery and wrong-key rejection.

### Cleanup and Async Settlement

**Source:** `private-channel.test.ts` lines 123-140; `community.test.ts` lines 150-161  
**Apply to:** both integration tests

Wait for the existing async folds, then unsubscribe and dispose engines at the end of each test. Continue using the injected fake/serving pools; do not add network access.

### No Runtime Storage Pattern

**Source:** `packages/concord/src/client/storage.ts` lines 66-74

```typescript
export interface ConcordUploader {
  upload(file: Blob, communityId: string, options?: ConcordUploadOptions): Promise<MediaAttachment>;
}
```

There is no fetch/download/decrypt method to modify. Do not invent one for D-03; runtime failure attachment remains downstream-consumer territory until a real boundary exists.
