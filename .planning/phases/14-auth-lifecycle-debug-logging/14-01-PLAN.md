<objective>
Replace `RelayAuthContext`'s three-value `operation` bucket with an exhaustive wire-verb discriminated
union carrying the request the relay actually refused, give `negentropy()` ownership of its NEG-OPEN
subscription id, and land the shared request-summary/truncation formatter both log tracks will use.

Purpose: relays gate auth on request *shape*, not on a category — a three-value bucket cannot describe
what a relay is demanding, and every downstream log line in this phase needs a stable per-operation
identity to hang off (D-02, D-05, D-06). This is also the plan that re-verifies D-01's release-window
premise before any API widening lands.

`packages/relay/src/helpers/auth-log.ts`, the D-03 verb-to-flag adapter and `satisfiedPubkeysFor` on
`Relay`, an `id` parameter on `negentropySync`, and updated operator config plus test fixtures.

Create a new internal module `packages/relay/src/helpers/auth-log.ts`. It must import only types (`import type { Filter } from "applesauce-core/helpers/filter"` and `import type { RelayAuthWireRequest } from "../types.js"`) so it carries no runtime dependency on `relay.ts`. Export three numeric constants — `AUTH_LOG_TEXT_LIMIT` (256), `AUTH_LOG_ID_LENGTH` (8), `AUTH_LOG_KINDS_LIMIT` (20) — and four functions:

`truncateForLog(value: unknown, limit = AUTH_LOG_TEXT_LIMIT): string` coerces a non-string to a string (empty string for `null`/`undefined`), returns it unchanged when its length is at most `limit`, and otherwise returns the first `limit` characters followed by a suffix naming how many characters were dropped. This is the T-14-01 mitigation — every relay-supplied free-text value in this phase's log lines goes through it.

`shortId(id: string, length = AUTH_LOG_ID_LENGTH): string` returns the leading `length` characters of `id` (unchanged if already shorter), giving a display-only prefix that still greps against the relay's own server log.

`summarizeFilter(filter: Filter): string` renders one filter as space-joined `key=value` pairs in this order — `kinds` first when present, then the filter's remaining keys in their own key order. `kinds` is spelled out as a bracketed comma-separated list capped at `AUTH_LOG_KINDS_LIMIT`, with an explicit trailing marker naming how many kinds were elided beyond the cap. `limit`, `since`, and `until` print their numeric value directly. `search` prints its character count rather than its text. Every other key — `ids`, `authors`, any `#`-prefixed tag key, and any unknown key — prints the array length when the value is an array and `1` otherwise. An object with no keys renders as a short fixed placeholder rather than an empty string.

`summarizeFilters(filters: Filter[]): string` returns a fixed placeholder for an empty array, delegates to `summarizeFilter` for a single-element array, and for two or more filters returns the filter count followed by the deduplicated first-seen-order union of every filter's kinds (capped the same way), or just the count when no filter declares kinds.

`describeAuthRequirement(requirement: AuthRequirement): string` (importing `AuthRequirement` as a type from `../types.js`) renders what an operation is waiting for in prose: a boolean requirement as a phrase naming any authenticated pubkey, a single pubkey as that pubkey, and an array as its comma-joined pubkeys. Plan 14-05's operation track uses it for the "now waiting for …" line.

`describeWireRequest(request: RelayAuthWireRequest): string` switches on `request.verb` and returns, for `REQ` and `COUNT`, the verb followed by `shortId(request.id)` followed by `summarizeFilters(request.filters)`; for `EVENT`, the verb followed by `shortId(request.event.id)` and `kind=<event.kind>`; for `NEG-OPEN`, the verb followed by `shortId(request.id)` and `summarizeFilters([request.filter])`. The switch ends with a default branch that assigns the narrowed `request` to a `never`-typed local so a fifth union member added later fails to typecheck here rather than silently falling through.

Write `packages/relay/src/helpers/__tests__/auth-log.test.ts` covering, with expectations hand-derived from the rules above rather than copied from a first run: the D-06 example shape (a REQ whose filter has `kinds`, `authors`, a `#e` tag and a `limit` renders kinds spelled out and everything else counted); the kinds cap and its elision marker; the multi-filter union branch; `EVENT` and `NEG-OPEN` rendering; `shortId` truncation; and `truncateForLog` leaving a short string untouched while bounding an oversized one to `AUTH_LOG_TEXT_LIMIT` plus the suffix.
