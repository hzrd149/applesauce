the failing error, and a `group.test.ts` assertion proving both.

  <action>
Create `packages/relay/src/__tests__/debug-capture.ts` as a test-support module (not a `.test.ts` file, mirroring `fake-user.ts`'s placement convention). It imports the `debug` package's default export and `format` from `node:util`.

Export `captureDebugOutput(namespace: string): { calls: unknown[][]; restore: () => void }`. It records whether the namespace was already enabled, calls the package's `enable` with the supplied namespace, saves the current shared output sink, replaces it with a collector that pushes every argument array into a `calls` array, and returns `calls` together with a `restore` that puts the original sink back and disables the namespace only when it was not enabled beforehand. Take the namespace as a parameter rather than hardcoding it — plan 14-06 targets `Relay`'s auth sub-namespace while this plan targets `RelayGroup`'s.

Export `messagesOf(calls: unknown[][]): string[]`, rendering each captured call through `format(...)` so assertions compare against the same substitution result a real terminal would show. Do not hand-roll printf substitution.

Export a small convenience `withDebugCapture<T>(namespace: string, body: (lines: () => string[]) => T | Promise<T>): Promise<T>` that runs `body` inside a `try`/`finally` and always calls `restore`, handing `body` a getter that renders the currently captured calls. This exists so a test cannot forget the `finally` — Pitfall 4's leak is a real hazard because `debug`'s enable state and sink are module-level singletons shared by every test in the same file.

Document at the top of the module, in a short comment block, the two facts a future reader needs: the enable state is global to the file's module registry so restore is mandatory on every path including failures, and the package's wildcard crosses namespace segments (a namespace glob ending in a wildcard matches deeper children), which is why a broad capture will also collect sub-namespace lines.

Add no assertions and no `describe`/`it` blocks — this module is infrastructure consumed by `group.test.ts` in Task 2 and by the lifecycle oracle in plan 14-06.
  </action>
