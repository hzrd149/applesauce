# Phase 25.4 Pattern Map

**Mapped:** 2026-09-06

| Planned area | Closest existing analog | Direction |
|---|---|---|
| `packages/core/src/logger.ts` | Existing single construction point and root barrel export | Keep `logger` as the stable root; add the local callable type and controls here. |
| `packages/relay/src/__tests__/debug-capture.ts` | Its `try/finally` global capture helper | Preserve restoration and wildcard semantics while changing the control source. |
| Concord logger injection | Existing `Debugger`-typed options and callable spies | Import the core-owned type; preserve structural injected spies and constructor-time `.extend()`. |
| Signers/wallet/wallet-connect | Existing imports of both `logger` and `Debugger` | Co-locate runtime/type imports from `applesauce-core`; avoid duplicate type authorities. |
| Package cleanup | Phase 16/25 ecosystem manifest migrations | Modify each package manifest with its source migration and regenerate the root lockfile last. |

## Critical Interfaces

- `packages/core/src/index.ts` already exports `./logger.js`; declarations added in `logger.ts` become root exports without a new barrel.
- Relay and Concord capture must operate on the same module-level namespace state and sink used by every core-derived logger.
- Concord's `logger` is `coreLogger.extend("concord")`; its public logger injection remains callable and extendable.
- Existing tests use `node:util.format` only to render captured arguments in tests; production replacement must remain browser-safe.

## Avoid

- A second logger type copied into consumer packages.
- Cached enablement at logger creation time.
- A Node-only production formatter import.
- Broad compatibility work for upstream APIs with no workspace caller.
