<objective>
Close WR-05 and WR-08: the shipped examples contradict the invariant this phase exists to
enforce, and the guard that is supposed to watch them only watches one of its four checks.

**WR-05**: `crypto-history.tsx:49`, `rumor-stores.tsx:43` and `direct-invites.tsx:36` each
declare `const streamSigners = new StreamSigners();` at module scope, with a comment asserting
"this walk covers one community, so this module-level holder is that scope's holder". That is
not true of a module-level binding — it outlives the React component, so pasting a second
invite link or material (the entire point of these walkers) accumulates both communities'
secret keys in one holder. The per-operation `missingPubkeys` narrowing still prevents
cross-authentication at the wire, but the holder split is the load-bearing D-06 invariant the
package advertises, and these examples are the package's primary documentation of the new API.
A reader copies the singleton into a multi-community app and loses the guarantee.

**WR-08**: `no-ambient-auth.test.ts` collects `EXAMPLES_ROOT` and includes it in the
`REMOVED_MECHANISMS` sweep, but `AMBIENT_AUTH_TRIGGER`, `RETRY_BUDGET_OVERRIDE` and
`MISSING_PUBKEYS_FIELD` (`:93-127`) filter to `SRC_ROOT` only. Since the examples are the code
most likely to be copied, they are the MORE important root for the ambient-trigger check, not
the less. The examples are currently clean of all three patterns, so widening the guard is
safe today — which is exactly why it should be done now rather than after a violation lands.

Purpose: make the shipped documentation-by-example demonstrate the per-scope-holder invariant
rather than contradict it, and make the structural guard's name honest.

Output: three examples with scope-lifetime holders, and a guard whose four checks share one
two-root file list.
</objective>
