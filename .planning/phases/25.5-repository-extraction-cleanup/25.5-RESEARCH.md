## Common Pitfalls

### Pitfall 1: The Verification Command Matches Its Own Planning Records

**What goes wrong:** A literal sweep remains nonzero because the phase directory, title, context, research, plans, summaries, roadmap, and state describe the removed package. [VERIFIED: current phase path/content]

**How to avoid:** Make planning-artifact deletion/neutralization the final task, retain any needed instructions outside the repository, and only then run the no-exclusion gate. [VERIFIED: constraint analysis]

### Pitfall 2: Generated Artifacts Reintroduce Matches

**What goes wrong:** VitePress output or stale node_modules links retain old content even after tracked files are clean. [VERIFIED: current ignored artifacts]

**How to avoid:** Clean/rebuild applicable apps, reinstall/prune workspace links, and search ignored files and names separately. [VERIFIED: environment inspection]

### Pitfall 3: Broad Deletion Erases Unrelated Applesauce History

**What goes wrong:** Entire mixed milestone or planning files are removed even though D-03 requires unrelated history to survive. [VERIFIED: user constraint]

**How to avoid:** Whole-delete only package-specific artifacts/directories; line- or section-edit shared files, then review their diffs. [VERIFIED: repository inventory]

### Pitfall 4: Treating `null` as Parse Failure

**What goes wrong:** A truthiness guard rejects valid JSON values `false`, `0`, `null`, and `""`. [VERIFIED: existing regression test]

**How to avoid:** Use `data === undefined` as the parse-failure sentinel; preserve the table-driven test in `packages/common/src/helpers/__tests__/app-data.test.ts`. [VERIFIED: codebase inspection]
