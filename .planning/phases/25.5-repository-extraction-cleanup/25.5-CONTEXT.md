<decisions>
## Implementation Decisions

### Complete Concord Removal
- **D-01:** No Concord code, documentation, examples, configuration, changesets, lockfile entries, or textual references may remain in the checked-out repository after this phase.
- **D-02:** Delete Concord-specific historical phase and milestone artifacts entirely rather than preserving them as local history. — **Reversibility:** costly — restoring these records would require recovering them from Git history or the new Concord repository.
- **D-03:** Edit mixed or shared historical documents to remove their Concord material while preserving unrelated Applesauce history.
- **D-04:** Remove pending `applesauce-concord` changesets rather than migrating them into the core repository's release history; the separate Concord repository owns future release records.
- **D-05:** Regenerate package-manager metadata after removing the workspace package and consumers so no `packages/concord` link or `applesauce-concord` dependency remains.

### Phase 05.1 Review Follow-ups
- **D-06:** Fold all three still-open items from `.planning/todos/pending/05.1-review-followups.md` into this phase: correct the stale `stamp` comment, clear `WalletRelaysSymbol` in `lockWallet`, and make `getAppDataContent` handle falsy parsed values correctly.
- **D-07:** Treat the closed entries in that todo as historical evidence only; do not reopen them.

### Verification Boundary
- **D-08:** Verification must use a repository-wide zero-match sweep for Concord names and paths, not an allowlist for historical material.
- **D-09:** Build and test the remaining workspace after lockfile regeneration, and add focused regression coverage for the two behavioral Phase 05.1 fixes.

### the agent's Discretion
- Choose the exact decomposition between Concord deletion, shared-document scrubbing, package-manager regeneration, and the three Phase 05.1 fixes.
- Choose focused test locations that follow the existing wallet, app-data, and event-symbol test patterns.

### Folded Todos
- **Phase 05.1 code-review follow-ups (deferred, mostly pre-existing):** close the three remaining cosmetic items during this repository cleanup so they do not survive into Phase 26 release coordination.

</decisions>

## Existing Code Insights

### Reusable Assets
- Workspace scripts and Turbo tasks provide the remaining-package build and test verification surface.
- Existing focused tests around event symbols, wallet locking, and app-data parsing provide homes for the folded regression cases.

### Established Patterns
- The monorepo uses pnpm workspaces and a generated `pnpm-lock.yaml`; workspace removal must be reflected by regeneration rather than hand-editing.
- Changesets link publishable packages in `.changeset/config.json`; removing Concord changes the Phase 26 release set from fourteen to thirteen packages.
- VitePress navigation and the examples app explicitly register Concord content and must be cleaned together with their source trees.

### Integration Points
- `packages/concord/`, `apps/docs/concord/`, and `apps/examples/src/examples/concord/` are the primary Concord-owned trees.
- `apps/examples/package.json`, `.changeset/config.json`, pending Concord changesets, VitePress configuration, and `pnpm-lock.yaml` are active integration and release surfaces.
- Shared source comments, current planning files, archived milestone files, and completed phase directories contain textual Concord references covered by the zero-residue rule.
