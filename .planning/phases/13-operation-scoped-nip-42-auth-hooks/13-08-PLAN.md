<objective>
Close CR-01, CR-04 and WR-01 at their source: the shared D-04 operator module.

**Structural choice (stated explicitly per planning directive 1):** CR-01 and WR-01 are the same
defect class — a call site's *bookkeeping* value (`req()`'s synthetic `OPEN`) being counted as real
progress by a shared consumer that has no way to ask. The fix is NOT to special-case `OPEN`. It is to
make "what counts as progress" a **required, typed parameter** at both consumers:
`authRetry`'s D-08 consecutive-counter reset and `suspendableTimeout`'s first-emission gate. Because
the parameter is required (not optional-with-a-permissive-default), a future call site that introduces
a new bookkeeping value cannot silently re-break the retry bound or the operation clock — omitting the
answer is a TypeScript compile error, not a runtime surprise.

**Explicitly rejected alternative:** adding `subscribeOn(asapScheduler)` (or any scheduler hop) to
`authRetry`'s `expand` resubscribe as a blanket fix for CR-02/CR-03. That would make stream-shape
correctness depend on scheduler timing rather than on structure, and it duplicates the send/listen
split 13-05 already committed the codebase to for `event()`. CR-02/CR-03 are fixed by applying that
same shape uniformly at the call sites in plans 13-09 and 13-10. Do not add a scheduler hop here.

CR-04 is a separate, independent defect in the same file: `config.onAuthRequired?.(context)` is
invoked inside the `defer` factory *above* the `catchError` that maps rejections, so a synchronous
throw bypasses `errors.handler` entirely and reaches the caller as a raw `Error`.

Purpose: RAUTH-03's bound and RAUTH-08's D-16 fallback guard both currently depend on properties the
shared operator does not actually enforce. This plan makes them enforceable.
Output: an operator surface where "progress" and "first emission" are explicit obligations, a handler
invocation whose failures are always mapped, and operator-level regression tests that fail against
today's code.
</objective>
