<objective>
Convert `negentropy()` to the shared auth operator, replace `Relay.sync`'s anonymous option literal with
`RelaySyncOptions` (D-05), close the gap 13-RESEARCH.md found — `sync()`'s two internal calls pass no
options at all — and delete the now-dead pre-gate helper that caused RAUTH-02.

Purpose: this is the last of the four auth sites and the direct prerequisite for Phase 15's
stream-key-scoped auth, which must apply uniformly across everything `sync()` does rather than only its
negotiation.
Output: an auth-operator-driven `negentropy()`, a `sync()` whose options reach all three of its relay
operations, a relay.ts with no pre-block mechanism left, and tests.

## RESEARCH gap 4 — sync()'s internal calls: CLOSED HERE

`sync()` internally calls `this.event(event)` for the SEND direction and `this.req({ ids: need })` for the
RECEIVE direction with no options argument. Today the ambient pre-block flags gated those calls
consistently with the outer negotiation. Once the pre-block is gone they each independently default to
`waitForAuth: true` with no handler and, per D-14, wait up to the 30s default for any pubkey — entirely
disconnected from what the caller configured. Task 2 threads `sync()`'s own options into both. Neither the
999.5 draft nor 13-CONTEXT.md's canonical refs mention these two call sites.

## Artifacts this phase produces

This plan creates no new exported symbols. It consumes `RelaySyncOptions`, `RelayAuthOptions`,
`AuthHandlerError`, `AuthTimeoutError`, `authRetry`, `AuthPhaseGate`, `AuthRequiredSignal` and
`Relay.authRetryOperator` — created earlier in this phase by plan 13-01 — and the converted `event()` and
`req()` from plans 13-02 and 13-05. Drift verification must treat those as new. This plan also REMOVES one
pre-existing protected member: the auth pre-gate helper that all four sites used as a pre-block.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay -> client | the NEG-ERR reason string, translated at the negentropy edge, drives whether the negotiation retries, waits, or errors |
| client app -> library | `onAuthRequired` runs arbitrary caller code inside the sync pipeline, now on three distinct relay operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Denial of Service | `negentropy()` re-negotiation and `sync()`'s internal calls | high | mitigate | A relay rejecting every negotiation is bounded by the shared operator's consecutive counter and per-phase `authTimeout`. Threading the caller's options into the two internal calls also brings them under the caller's chosen bounds rather than leaving each on the 30s default with no handler, so a sync against a hostile relay cannot multiply three independently defaulted waits. |
| T-13-02 | Repudiation | edge translation in `negentropy()` | medium | mitigate | A `NegentropyError` whose reason is not an auth prefix still re-throws its own typed error, so a genuine negentropy protocol failure is never reported as an auth failure; conversely a handler rejection is `AuthHandlerError`. Plan 13-03's fallback gate depends on this separation holding. |
| T-13-03 | Tampering | sync's three relay operations authenticating the same pubkey | low | accept | The negotiation, the EVENT send and the REQ may each invoke the handler and drive an AUTH within one `sync()` call. Accepted per RAUTH-05; the alternative is exactly the relay-internal dedupe REQUIREMENTS.md places out of scope. Callers that want one prompt implement it in their handler. |
| T-13-SC | Tampering | package-manager installs | n/a | accept | Not applicable — no dependency is added by this plan. |
</threat_model>
