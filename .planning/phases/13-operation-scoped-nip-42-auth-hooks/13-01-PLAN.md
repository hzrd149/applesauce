## Open Question 1 — timeout suspension mechanism (D-15): RESOLVED

The shared operator owns it. `operators/auth-retry.ts` exports an `AuthPhaseGate` (a per-operation
counter of in-flight auth phases) and a `suspendableTimeout` operator whose countdown only advances
while the gate is inactive. `authRetry` opens the gate before an auth phase and closes it after,
so `count`'s 10s, `request`'s 30s, and `publish`'s `publishTimeout` are all re-expressed as
`suspendableTimeout` against the same gate. For `request` and `publish` the gate is created by the
outer method and threaded into the inner `req`/`event` call through a module-private symbol key
(`AUTH_PHASE_GATE`) on the options object, so the gate is never part of the public option surface.
This is one mechanism, not three bespoke per-call-site fixes.

## Open Question 3 — error `.name` strings: RESOLVED

`AuthHandlerError` sets `this.name = "AuthHandlerError"` and `AuthTimeoutError` sets
`this.name = "AuthTimeoutError"`, matching the existing convention on `RelayClosedError` and
`AuthRequiredError`. Because `applesauce-loaders` cannot import these classes (D-06 forbids the
dependency), those exact strings are load-bearing wire between the two packages. A comment at the
class definition site must say so and name `packages/loaders/src/loaders/sync-loader.ts` as the
coupled consumer; plan 13-03 adds the mirrored comment at the check site.

Create `packages/relay/src/operators/auth-retry.ts`. It must not import anything from `./relay.js`; it
may import types from `../types.js` and operators from `rxjs`. Export:

`AUTH_REQUIRED_SIGNAL` — a module-level unique symbol used as the discriminant key.
`AuthRequiredSignal` — the internal value type carrying that key plus a `reason` string.
`authRequiredSignal(reason)` — factory.
`isAuthRequiredSignal(value)` — type guard.

`AuthPhaseGate` — a small class tracking how many auth phases are currently in flight for one operation
subscription. It exposes `begin()`, `end()`, and an `active$` observable of booleans that is true while
the count is above zero (distinct-until-changed). Use a counter rather than a boolean so overlapping
phases within one operation cannot resume the clock early. Gates are created per operation call and hold
no relay-scoped state, which is what makes RAUTH-05's independence structural rather than enforced.

`AUTH_PHASE_GATE` — a module-level unique symbol, plus a `WithAuthPhaseGate` type describing an object
carrying an optional `AuthPhaseGate` under that key. This is how an outer operation (`request`, `publish`)
hands its gate to the inner operation (`req`, `event`) without the gate appearing in any public option
type. Document that intent in the JSDoc.

`suspendableTimeout(budgetMs, gate, opts?)` — a mono-type operator implementing first-emission timeout
semantics (matching every call site it replaces) whose countdown only advances while the gate is
inactive. Time spent inside an auth phase does not consume the budget, and the operation gets the full
remaining budget for real work afterwards (D-15). `opts.with` mirrors the rxjs `timeout` `with` escape
hatch so `count` can keep producing its own error and `event` can keep producing its own timeout
response value. A non-positive or non-finite budget returns identity.

`authRetry(config)` — the D-04 operator. It is an `OperatorFunction` from a stream that may carry
`AuthRequiredSignal` values to a stream that never does. `config` carries: `operation` (the
`RelayAuthOperation` label), `waitForAuth`, `onAuthRequired`, `authTimeout`, `authRetries`,
`buildContext(reason)`, `authSatisfied$()`, `gate`, `log`, and `errors` (three constructors:
`exhausted(reason)`, `handler(reason, cause)`, `timeout(reason)`). Behavior:

1. Values that are not signals pass through untouched.
2. Receiving a signal never errors the stream and never re-emits the signal downstream (D-01).
3. If `waitForAuth` is false, terminate immediately with `errors.exhausted(reason)` and do not call the
   handler at all (RAUTH-06).
4. If the consecutive-auth-failure counter has already reached `authRetries`, terminate with
   `errors.exhausted(reason)`. With the default `authRetries` of 1 this means the source is subscribed at
   most twice, so at most `authRetries + 1` protocol sends occur (D-07, RAUTH-03).
5. Otherwise open the gate, then run ONE auth phase: build the context, invoke `onAuthRequired` when
   present (always invoking it, even when the requirement is already satisfied — D-11), then wait for
   `authSatisfied$()` to emit true. Handler rejection maps to `errors.handler(reason, cause)`.
6. The handler invocation and the subsequent wait are wrapped in a SINGLE timeout of
   `authTimeout ?? 30_000` ms, or no timeout at all when `authTimeout` is false (D-12, D-14). Expiry maps
   to `errors.timeout(reason)`. A fresh clock is created for every auth phase (D-13).
7. Close the gate on every exit path from the phase, including error and unsubscribe.
8. Re-subscribe the operator's own source immediately with no delay (D-10), the same way rxjs `retry`
   re-subscribes on error, incrementing the consecutive counter.
9. Any non-signal value emitted after an auth phase resets the consecutive counter to zero, so
   `authRetries` means consecutive auth failures tolerated rather than a per-lifetime budget (D-08).

The `expand()` sketch in 13-RESEARCH.md is the recommended starting idiom but is explicitly non-binding
(Assumption A1); any idiom is acceptable that keeps the signal off the error channel and preserves the
ordering above.

Create `packages/relay/src/__tests__/auth-retry.test.ts` covering the operator in isolation with real
timers and small explicit values (D-20 — the relay suite uses no fake timers; do not introduce them):
