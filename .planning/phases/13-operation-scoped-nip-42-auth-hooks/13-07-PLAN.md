Finish RAUTH-07's pool and group leg, land D-18 and D-19 on the group's publish and sync paths, convert the
last two anonymous option literals to derived types (D-05), write the changesets, and close the phase's
validation record.

pass-through tests, the changesets, and a filled-in VALIDATION.md.

  <action>
Convert both hand-declared sync option literals to derived types, matching the sibling pattern already used
by `count` and `event` in the same two classes (D-05, literals 4 and 5). `RelayGroup.sync`'s options
parameter derives from `Relay`'s `sync` signature; `RelayPool.sync`'s derives from `RelayGroup`'s. Deriving
rather than retyping in place is the point: it makes a future added option propagate automatically instead
of requiring three coordinated edits that TypeScript cannot enforce.

Add per-relay isolation to `RelayGroup.sync` (D-19). The method currently merges every relay's `sync()`
observable with no catch, so one relay's error kills the whole group sync. Give each relay's observable its
own catch that logs the dropped relay and continues with an empty stream, matching the shape the REQ path
and the publish path already use at the fan-out boundary. `sync()` returns a bare event observable with no
error channel, so per D-19 the dropped relay is visible in debug output only; that is Phase 14 territory
and this plan should not invent a status channel for it. Keep the existing behavior where zero NIP-77-capable
relays still throws, since that is a configuration error rather than a per-relay failure.

Extend `errorToPublishResponse` to attach the caught error object on the response's new optional `error`
field alongside the existing message fallback (D-18). Today the group's REQ path preserves the error object
while its publish path keeps only a message string, so a group publish that fails auth reaches a consumer as
text it cannot branch on — the exact thing Phase 15 needs. Do not change the existing `ok` or `message`
behavior; the field is purely additive.

Confirm `RelayGroup` and `RelayPool` gain no auth logic beyond forwarding options and isolating failures —
every other method already derives its option type and therefore picks the new fields up with no edit
(RAUTH-07's pool leg).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Denial of Service | `RelayGroup.sync` fan-out | high | mitigate | Without D-19's per-relay catch, one hostile or auth-gated relay in a group terminates the sync for every other relay — a single-relay problem escalated into a group-wide outage. | T-13-02 | Repudiation | `errorToPublishResponse` | medium | mitigate | D-18's `error` field is what stops a group publish failure from arriving as an unattributable string; with the typed auth errors attached, a consumer can tell a handler bug from a relay rejection from a timeout, which is exactly the branching Phase 15 needs. |
