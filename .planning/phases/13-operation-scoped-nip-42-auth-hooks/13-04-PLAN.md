<objective>
Convert `count()` to the shared auth operator, replace its anonymous option literal with the named
`RelayCountOptions` type (D-05), and re-express its hard 10s COUNT clock as a suspendable one so a COUNT
can survive an auth round-trip (D-15).

Purpose: `count()` is the clearest demonstration of D-15 — 13-CONTEXT.md names it as the motivating case,
because a 10s budget cannot absorb a 30s default `authTimeout` and a COUNT that hits auth-required today
can never succeed once the pre-block is gone.
Output: a `count()` with no pre-block, no catch-and-rethrow, a named option type, and a suspended
operation clock, plus wire-trace tests.

## Artifacts this phase produces

This plan creates no new exported symbols. It consumes `RelayCountOptions`, `RelayAuthOptions`,
`AuthHandlerError`, `AuthTimeoutError`, `authRetry`, `suspendableTimeout`, `AuthPhaseGate`,
`AuthRequiredSignal` and `Relay.authRetryOperator` — all created earlier in this phase by plan 13-01.
Drift verification must treat those as new, not as drift from existing source.
</objective>

|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Denial of Service | `count()` retry path | high | mitigate | Making the 10s clock suspendable removes the incidental bound that previously killed an auth-looping COUNT, so the deliberate bounds must carry it: the shared operator's consecutive counter caps COUNT frames at `authRetries + 1` and each phase has its own `authTimeout`. | T-13-02 | Repudiation | `onAuthRequired` invocation in `count()` | medium | mitigate | A rejecting handler yields `AuthHandlerError` with the original rejection as `cause`, distinct from `AuthTimeoutError` and from the COUNT-timeout error the operation clock produces — three distinguishable failures instead of one opaque one. |
