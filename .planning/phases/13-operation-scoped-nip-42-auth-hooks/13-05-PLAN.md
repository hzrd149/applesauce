<objective>
Move `event()`'s post-response auth wait onto the shared operator, replace its anonymous option literal
with `RelayEventOptions` (D-05), suspend `publish()`'s `publishTimeout` across the auth phase (D-15), and
close the gap 13-RESEARCH.md found: `customRetryOperator` — the retry `publish()` uses — has no
`RelayClosedError` skip, unlike its sibling. Without that skip, removing the pre-block turns publish's
existing three-retry linear-backoff loop into exactly the hot loop D-07 exists to prevent.

Purpose: `event()` already emits `{ ok: false, message: "auth-required:" }` as a value, so it is the
model the rest of the phase copies (D-02). What changes is where the wait and the retry live, and who is
allowed to retry an exhausted auth failure.
Output: an `event()` on the shared operator, a `publish()` with a suspended clock and a retry that cannot
loop on auth, and tests that pin the EVENT frame count.

## RESEARCH gap 1 — publish's missing RelayClosedError skip: CLOSED HERE

`customRetryOperator` (used only by `publish()`) is a bare `retry({...count})` with no error-type filter.
`customConnectionRetryOperator` has the `instanceof RelayClosedError` skip; `customRetryOperator` never
needed it because `AuthRequiredError` was consumed inside `event()`'s wait before reaching publish's pipe.
Under the new model the terminal auth failure does reach that pipe. Task 2 adds the equivalent skip. Its
blast radius is narrow and must be stated in the summary: `customRetryOperator` has exactly one caller
(`publish`), and the only `RelayClosedError` subtype that reaches it is the auth family, because `event()`
returns relay rejections as values rather than errors.
