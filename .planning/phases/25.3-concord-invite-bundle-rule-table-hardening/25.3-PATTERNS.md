**Structural typing seam** (lines 315-337): retain the discriminated rule union, but replace the value-blind mapping with conditional/indexed-access types derived from `T[K]`. Optionality must be computed separately from `Exclude<T[K], undefined>` so optional fields still select their present-value rule family.

```typescript
export type BundleFieldRule =
  | { kind: "hex-key"; onInvalid: "reject" | "drop"; onAbsent: "reject" | "omit" }
  | { kind: "bounded-text"; max: number; onInvalid: "reject" | "drop"; onAbsent: "reject" | "omit" | "empty-string" }
  | { kind: "safe-integer"; onInvalid: "reject" | "drop"; onAbsent: "reject" | "omit" }
  // array/object variants continue here
```

Use the existing indexed-access subject aliases (lines 343-346) rather than mirrored local interfaces. Preserve `RULE_TABLE_SUBJECT_PROOF` (lines 491-497) as the key-set proof, while adding value/rule compatibility proof. Declare the four table literals with `satisfies ExhaustiveBundleRules<Subject>` so literal `kind` and disposition values remain available to generated tests; the current explicit annotations at lines 371, 432, 457, and 471 widen them.

**Closed projection pattern** (lines 625-636): keep this exact rebuild-never-spread control flow. Adapt its types so iterating the table does not weaken projection coverage.

```typescript
const src = value as Record<string, unknown>;
const out: Record<string, unknown> = {};
for (const key of Object.keys(table)) {
  const result = applyFieldRule(table[key]!, src[key]);
  if (result.outcome === "reject") return undefined;
  if (result.outcome === "value") out[key] = result.value;
}
```

**Error handling pattern** (lines 509-580, 659-670): rule failure is represented as a discriminated outcome/`undefined`, while impossible rule kinds use a `never` exhaustiveness guard. Keep conversion exceptions behind successful structural validation and use narrow defense-in-depth catches only around crypto conversion.

**Optional-field rule:** lines 587-600 already distinguish absent input before validating present input, and lines 633-634 write only `"value"` outcomes. Preserve this mechanism; never assign `out[key] = undefined` and never normalize optional fields to `null`.

### `packages/concord/src/helpers/invite-list.ts` (utility/validator, transform)

**Primary analog:** `packages/concord/src/helpers/invite-bundle.ts` lines 603-636 (closed allowlist projection), combined with this file's open wire parser at lines 109-126.

The two boundaries are deliberately different:

- `parseInviteList` must remain an open document parser so unknown top-level fields round-trip.
- The new per-entry validator must return a fresh, closed `InviteListInvite` projection containing only declared entry fields.

**Open wire parser pattern** (lines 109-126): do not sanitize or rewrite here.

```typescript
export interface ParsedInviteList {
  entries: InviteListInvite[];
  tombstones: InviteListTombstone[];
  [k: string]: unknown;
}

const doc = JSON.parse(json) as ParsedInviteList;
return { ...doc, entries: doc.entries ?? [], tombstones: doc.tombstones ?? [] };
```

**Pure validation/projection pattern:** mirror the bundle helper's rule outcome approach. Validate `token`, `signer_sk`, `community_id`, `url`, `created_at`, and optional `label`, `channels`, `expires_at` before any `hexToBytes`/`getPublicKey` call. Rebuild by allowlist and conditionally add optional properties so omitted inputs remain absent. Return a typed success/failure result or `undefined`; do not throw for malformed persisted entry data.

**Existing local safety precedent** (lines 152-164): `getInviteBundleLocator` catches malformed URL parsing, but currently leaves `hexToBytes(invite.signer_sk)` outside the catch. The new entry validator should be the prerequisite for this and manager projection, rather than broadening the catch to hide schema corruption.

**CRDT invariant** (lines 58-75): keep `mergeInvites`/`mergeTombstones` deterministic and token-keyed. Validation should occur before a raw replacement is allowed to influence the trusted projection; do not change first-seen semantics as an incidental fix.

**Current failure point** (lines 376-397): replace the whole-array throwing map with per-entry validated projection. `getPublicKey(hexToBytes(...))` must only receive a validated secret key.


**Persistence separation** (lines 316-343): quarantine is read-side state. Do not call `markDirty()` or `save()` because an entry was rejected. Preserve the raw/open document carrier and existing fingerprint behavior so corruption is never silently repaired or republished.

## Shared Patterns

### Trust-Boundary Projection

**Source:** `packages/concord/src/helpers/invite-bundle.ts` lines 603-636  
**Apply to:** bundle and persisted invite-entry validators.

Iterate declared rules/fields into a fresh object, reject early on required structural failure, write only accepted values, and never spread untrusted input.

### Optionality Preservation

**Source:** `packages/concord/src/helpers/invite-bundle.ts` lines 587-600 and 630-635  
**Apply to:** every optional bundle and invite-list entry field.

Treat absence before present-value validation; `omit` means no own key is written.

### Typed Reactive Diagnostics

**Source:** `packages/concord/src/client/rotation.ts` lines 5-14 and 56-62  
**Apply to:** `ConcordInviteManager` corrupt-entry reporting.

Expose a read-only observable backed by a private subject; use literal status/reason unions and non-secret source identifiers.

### Fail-Soft Batch Reconciliation

**Source:** `packages/concord/src/helpers/invite-bundle.ts` lines 533-548 (bad channel drops, valid sibling survives) and manager lines 346-362 (single reconciliation commit point)  
**Apply to:** invite-list entry batches.

Classify entries independently, retain prior trusted state for identifiable corrupt replacements, then emit one coherent next projection.

### No Repair Publish

**Source:** `packages/concord/src/client/invite-manager.ts` lines 316-343  
**Apply to:** quarantine handling.

Only explicit local record/tombstone operations mark dirty and save. A read-side diagnostic must not mutate the wire carrier, fingerprint, or publication state into a sanitized rewrite.
