# Quick Task 260804-g7f: wallet undefined over throw

Findings #3, #4, #5 from the throw/undefined review — the remainder after 260804-g0c
took #1 and #2. Same defect class as `gift-wrap.ts` (422ce62b) and `getHiddenTags`
(a587410b): a getter whose return type already includes `| undefined` throws on
malformed or hostile input instead of returning it.

## Why the call sites make this safe

Every direct dereference of `getTokenContent(...)` in `actions/tokens.ts` is already
gated by `isTokenContentUnlocked`, and `isTokenContentUnlocked` currently converts the
throw into `false` via its own catch — so the filtered sets are **identical** before and
after this change. Only the mechanism differs.

The casts are already written for the undefined contract:
- `casts/wallet-token.ts:25/56` — `this.meta?.proofs`, and `map(... getTokenContent(event))`
  followed by `defined()` in the pipe.
- `casts/wallet-history.ts:25/52` — `this.meta?.direction`, same pipe shape.
- `actions/tokens.ts:680/689` — already `if (!firstTokenContent) throw ...`.

A throw inside those `map()` operators errors the observable, which is terminal — one
corrupt token would kill the wallet's meta stream, not just skip an event.

`getNutzapP2PKPubkey` has **zero callers** in the repo (public API only), and its own
dependency `getProofP2PKPubkey` (`helpers/cashu.ts:25`) already uses `safeParse` and
returns undefined for every failure — so the throw is inconsistent one level down.

All three `unlock*` counterparts already guard `if (!parsed) throw ...`, so they keep
throwing correctly once the getters return undefined.

## Task 1 — getTokenContent (packages/wallet/src/helpers/tokens.ts)

**action:**
- `JSON.parse` → `safeParse<TokenContent>`; return undefined when it yields nothing.
- Add a shape guard: `typeof details !== "object"` must return undefined **before** any
  property read. `safeParse("null")` yields `null`, and `null.mint` throws a TypeError —
  swapping one throw for another would defeat the point.
- `if (!details.mint) throw` and `if (!details.proofs) throw` → `return undefined`.
- Do NOT cache the rejection (return before `setCachedValue`), so a token stays readable
  if correct content is decrypted in later.
- Remove the now-dead `try {} catch {}` in `isTokenContentUnlocked` (typed param, and
  neither `isHiddenContentUnlocked` nor `getTokenContent` throws any more).
- Drop the `@throws` JSDoc; document the undefined contract.

**verify:** `npx vitest run packages/wallet` green; revert probe turns new tests RED.

## Task 2 — getHistoryContent (packages/wallet/src/helpers/history.ts)

**action:**
- Three throws (`missing direction`, `missing amount`, `Failed to parse amount`) →
  `return undefined`. Return before `setCachedValue`.
- Remove the now-dead `try {} catch {}` in `isHistoryContentUnlocked`. Doubly dead: its
  other call, `getHiddenTags`, stopped throwing in a587410b.

**verify:** as above.

## Task 3 — getNutzapP2PKPubkey (packages/wallet/src/helpers/nutzap.ts)

**action:**
- `throw new Error("Proof is not P2PK locked")` and
  `throw new Error("Proofs are locked to different pubkeys")` → `return undefined`.
  Nutzaps arrive from strangers; a non-P2PK or mixed-lock nutzap is hostile input, not a
  programmer error. The function already returns undefined for zero proofs, so this makes
  it internally consistent and matches `getProofP2PKPubkey` one level down.
- Replace the `@throws` JSDoc line with an accurate `@returns`.

**verify:** as above.
