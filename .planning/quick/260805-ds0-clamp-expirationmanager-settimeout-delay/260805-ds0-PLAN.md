<objective>
Fix three timer defects: two in `applesauce-core`'s `ExpirationManager` (unclamped
`setTimeout` delay causing a `TimeoutOverflowWarning` hot loop, and stale timer
bookkeeping that silently swallows later tracking), and one pair of sites in
`applesauce-wallet-connect`'s `waitForPaid()`.

Purpose: an untrusted NIP-40 `expiration` tag more than ~24.8 days in the future makes
Node clamp the delay to 1 ms and log `TimeoutOverflowWarning`. `emitNotifications()`
then finds nothing expired and immediately re-arms the same overflowing timer — an
unbounded hot loop that wrote a 16 GB syslog and exhausted a production host's disk
(hzrd149/nsite-gateway#28). Downstream is blocked waiting on a patch release.

Output: clamped and consolidated timer scheduling in both packages, regression tests
for all three defects, and three `patch` changesets.

Branch: already on `fix/clamp-settimeout-delays` at `origin/master` (4f2c1bbe) — no
branch work needed.
</objective>

    capped value there would break the guard. A capped early wake is a harmless no-op:
    `emitNotifications()` recomputes the minimum over remaining entries and expires nothing
    when nothing is due.

    Rewrite the tail of `track()` so its inline clear-and-arm block (currently lines 48-56)

    Rewrite the tail of `emitNotifications()` for D2: hoist the timer cleanup OUT of the

    bookkeeping, then call `this.scheduleNextCheck(nextExpiration, now)` only when
    `nextExpiration` is not `Infinity`. Since the helper already clears first, this reduces
    to guarding the helper call on the sentinel and clearing in the else path. Add a short
    comment explaining that the fired handle is spent and must not be left visible to
    `track()`'s guard.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay → EventStore | A NIP-40 `expiration` tag is attacker-controlled and arrives unvalidated in range. |
| wallet service → client | `transaction.expires_at` is supplied by the remote NWC service. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-ds0-01 | Denial of Service | `ExpirationManager.track` / `emitNotifications` | high | mitigate | Clamp the scheduled delay to `MAX_TIMER_DELAY` in `scheduleNextCheck()` so a far-future `expiration` tag cannot drive a 1 ms re-arm loop that floods syslog and exhausts host disk (Task 1). |
