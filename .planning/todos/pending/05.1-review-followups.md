Deferred findings from the Phase 05.1 advisory code review (`05.1-REVIEW.md`). WR-02 was
fixed in-phase (commit 44ec397f); the items below were triaged as pre-existing or
documented known-gaps and backlogged per user decision. None is a Phase 05.1 regression.

**Audited 2026-08-04** against live source during the v1.1 milestone close. Three of the
original six items were already fixed by intervening work but still described here as open —
corrected below. Priority dropped `high` → `low`: the only security-severity item (CR-01) is
closed, and what remains is cosmetic.

## CLOSED

### CR-01 (was BLOCKER, security) — author-spoofing via discarded verify — FIXED
`getGiftWrapSeal` now gates on `if (!isValidSeal(parsed)) return undefined;`
(`packages/common/src/helpers/gift-wrap.ts:254`), and `isValidSeal` calls `verifyWrappedEvent`.
The verify result is no longer discarded. The function carries an explicit rationale that this
is the sole insertion point for seals into `internalGiftWrapEvents`, so gating there is what
makes that set a set of authenticated seals.

### WR-03 (was WARNING) — getSealRumor undefined sentinel — FIXED
`isSealUnlocked` is now value-gated, not presence-only:
`RumorSymbol in seal || (isEncryptedContentUnlocked(seal) === true && getSealRumor(seal) !== undefined)`
(`gift-wrap.ts:137`), with the no-`undefined`-write invariant documented at `gift-wrap.ts:132-134`.
`getSealRumor` also gates on `isValidSeal` before its author binding.

### WR-01 (was WARNING) — replaceable version symbol copy — FIXED 2026-08-04
Closed by quick task `260804-hmw` (commits `200d9a85`, `4efd074f`, `55546e6b`).
`copySymbolsToDuplicateEvent` now carries a `readonly [symbol, DuplicateSymbolDisposition][]`
tuple list; `verifiedSymbol`/`EncryptedContentSymbol` are `"same-id-only"`, `FromCacheSymbol`
stays `"any-duplicate"`. The tuple arity makes adding a symbol without a disposition a compile
error, so the fix covers all six call sites (three in `event-store.ts`, three in
`async-event-store.ts`) by construction rather than by patching the reachable one.

### WR-04 (was WARNING, latent) — EventFactory.kind() never resolves — REMOVED 2026-08-04
Removed rather than fixed, per user decision (commit `e829d0a3`). The method had zero call
sites; its promise never resolved (the executor param was spread-and-discarded rather than
called); and changing kind mid-chain would have silently dropped preserved symbols anyway,
since `chain()`'s carry-forward is gated on `result.kind === draft.kind`. Patch changeset, since
no working code could have depended on a promise that never settles.

### INFO — `getGiftWrapSeal` throwing JSON.parse — FIXED
Now uses `safeParse` (`gift-wrap.ts:243`), matching concord's sibling.
