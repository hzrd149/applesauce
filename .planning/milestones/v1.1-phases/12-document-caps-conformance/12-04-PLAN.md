<objective>
Add the one shared UTF-8 byte-cap check D-03 requires and wire it into every write path that can
reach a published document: `createCommunity`, `createChannel`, and `editMetadata`. Cap values are
64 bytes for `name` and 10000 bytes for `description`, transcribed from CORD-02 §6 (D-05), enforced
by throwing (D-02), on the write side only (D-04).

Purpose: audit findings M17 and L09. `helpers/community.ts`'s `createCommunity` is exported public
API reachable with no client at all, so a client-only check leaves a bypass — hence D-03's
"enforce in the helpers". And `editMetadata`'s `{...current, ...patch}` merge re-publishes a `name`
that may predate the cap even when the patch only sets an icon, so the assertion has to run against
the merged result rather than the patch.

Output: a new `helpers/caps.ts`, three wired call sites, and spec-anchored tests exercising a
multi-byte string whose UTF-16 length and UTF-8 byte length differ.
</objective>
