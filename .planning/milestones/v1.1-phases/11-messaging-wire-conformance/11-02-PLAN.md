<objective>
Hard-remove the per-channel voice flag (D-06 / WIRE-01 / audit M13) from the type, the
write site, the fold, and both out-of-package consumers.

CORD-07 §1 and CORD-03 §2 both state that every Channel is callable and there is no
separate voice Channel type — the flag's own doc comment cites, as its authority, the
exact sentence that abolishes the concept. It is currently write-only inside
`packages/concord/src` but IS read by the example app's render path.

Per D-09 this is a deliberate breaking change with NO changeset: concord is unreleased,
so a changeset for a package with no consumers is noise. D-09 explicitly overrides
ROADMAP.md Phase 11 success criterion 1's "changeset + migration note included" clause —
criterion 1 scores on the field removal alone. Do not create a changeset file.

Purpose: removing the field from the type IS the structural guard (D-06) — `tsc` fails
any reintroduced read, so no additional runtime assertion is needed. That guard is only
meaningful if the whole workspace still builds.

Output: five files edited, unfiltered `pnpm build` green.
</objective>
