  <action>
behaviors that make TEST-01 auditable. Every case below must be a distinct `it()`:

1. `substituteFixtureTags` throws when a placeholder present in the fixture has no entry
   in `bindings`, and the thrown message names the unresolved token. This is the
   load-bearing non-vacuity guard: without it, a mis-typed binding would let a downstream
   assertion compare a real rumor tag against the literal placeholder text and quietly
   pass or fail for the wrong reason.
2. `substituteFixtureTags` passes non-placeholder elements through byte-identical —
   exercise this against `THREADED_REPLY_KIND1111_EXAMPLE`, asserting the `K` tag's value
   is still the literal 9 and the substituted `E` tag still has 4 elements with an empty
   string at index 2.
3. `missingFixtureTags` returns an empty array when `actual` contains every expected tag
   but in a DIFFERENT order and with extra unrelated tags interleaved — this is the case
   order.
4. `missingFixtureTags` returns the offending tag when a value differs (feed it an actual
   set whose k tag names 1111 against an expected set whose k tag names 9), and when an
   expected tag is absent entirely.
5. `tagValues` returns every value for a repeated tag name in encounter order, and an
   empty array for a name that is not present.
6. Every exported example's `section` matches an `examples.md` section pattern
   (`examples.md §` followed by a digit), its `tags` is a non-empty array whose every
   entry is a non-empty array of strings, and `CORD_EXAMPLES_CAVEAT` /
   `CORD_REPLY_ROOT_INHERITANCE_RULE` / `CORD_TARGET_KIND_RULE` are each non-empty. Drive
   this from an array of the five exported examples so a future added fixture is covered
   automatically rather than needing a new assertion.
  </action>

    - Case (6) iterates a collection of the exported examples rather than repeating one assertion block per example.
