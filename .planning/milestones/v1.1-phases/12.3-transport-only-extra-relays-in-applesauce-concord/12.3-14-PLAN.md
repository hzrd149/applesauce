## Why this design, and why the review's named fix alone is not it

The review's suggested repair (export the element types, map the table over them, add nested builder-coverage probes) is **necessary but not sufficient**: it fixes today's two instances and leaves the next anonymous inline type free to repeat the pattern. Four mechanisms were considered; three are adopted and one is rejected, deliberately:

| Mechanism | Verdict | Reasoning |
|---|---|---|
| **A. Rule-table subjects become indexed-access paths rooted at `InviteBundle`** (`NonNullable<InviteBundle["held_roots"]>[number]`, `InviteBundle["channels"][number]`, …), plus `rebuildByRules<T>(rules: ExhaustiveBundleRules<T>, …)` so the walker refuses a table that is not exhaustive over the type it returns | **ADOPTED — primary** | This is the root cause, stated exactly: the author wrote a duplicate *because* an anonymous inline type has no name to write `keyof Required<…>` against. It does have a path. Writing the subject as a path makes the table provably about the shape at that position of the real bundle — a hand-written mirror cannot be substituted, because the subject is not a name at all. It also deletes `validateInviteBundle`'s terminal `as unknown as InviteBundle`, the erasure the review named as the reason TypeScript never cross-checked the two. |
| **B. Compile-time key-set equality assertion (`RULE_TABLE_SUBJECT_PROOF`) covering all FIVE positions, including `channels[].held[]` and `held_roots[]` separately** | **ADOPTED — belt to A's braces** | A alone binds each table to one subject expression. B additionally pins that the *shared* held table's key set exactly equals the key set at BOTH held positions, in both directions (missing rule AND extra rule). If a future author re-inlines one of the two held element types and lets it drift from the other, B fires even though A's single subject is still satisfied. Cost: one exported const and one conditional type. |
| **C. Test-level tripwire asserting every `*_FIELD_RULES` export is annotated `ExhaustiveBundleRules<>` over a subject derived from `InviteBundle`** | **ADOPTED — independent of A and B** | A and B are both type-level: if a future author reaches for a local shape again, they must also *defeat* A and B to do it, and the most likely way to defeat them is to write a new table with a new hand-declared subject and no proof entry. C fires on that, from outside the type system, and generalises to a fifth table nobody has written yet because it discovers table names from the source instead of enumerating them. Implemented as a meta-test rather than a custom ESLint rule: identical firing condition, ~25 lines, no new lint plugin infrastructure in a repo that has none for this package. |
| **D. Remove all type erasure from the walker (a fully typed schema system, no `as T` anywhere)** | **REJECTED** | Would be the fifth structural rewrite of this one file inside a single phase, with a blast radius far larger than the defect it closes and a real chance of introducing the round-5 defect the round-6 review then finds. A + B + C make the specific class both unrepresentable and doubly detectable without re-litigating the walker's shape. Recorded here so the choice is visible rather than implicit. |
