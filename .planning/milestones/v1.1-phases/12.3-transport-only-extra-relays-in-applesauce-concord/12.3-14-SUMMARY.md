# Phase 12.3 Plan 14: Close CR4-01 as a class, WR4-01, WR4-02 Summary

**Rule-table subjects in `invite-bundle.ts` become indexed-access paths rooted at `InviteBundle` (not hand-declared mirrors), a five-position compile-time proof and a source-level meta-test independently pin both held positions, and `ConcordClient.handleRemoved`'s prune gets a behavioral test driven through the real `onRemoved` wiring.**

## Accomplishments

- `HeldKeyEntry` exported from `types.ts`, used by BOTH `ChannelKey.held` and `JoinMaterial.held_roots` — one named type for a shape two positions must share.
- `ExhaustiveBundleRules<T>` + four derived indexed-access aliases (`BundleChannel`, `BundleChannelHeldEntry`, `BundleHeldRootEntry`, `BundleIcon`) replace the CR4-01 defect (a hand-declared local `HeldRootEntry` mirror) — every rule table's subject is now provably the real shape at that position of `InviteBundle`.
- `RULE_TABLE_SUBJECT_PROOF`, a five-element compile-time proof, pins all five bundle positions — including `held_roots[]` and `channels[].held[]` independently — so the shared `HELD_KEY_FIELD_RULES` table can never silently diverge from either real position.
- `rebuildByRules<T>` now takes the narrow `ExhaustiveBundleRules<T>` (refusing a table not exhaustive over `T`); `validateInviteBundle` returns a directly-typed `InviteBundle` with no terminal `as unknown as` assertion.
- Four new conformance-suite probes (nested rule coverage, nested builder coverage, nested unknown-key rejection, and a source-level meta-test) catch the CR4-01 class even if the type-level derivation is later weakened.
- All six required demonstration probes (four field-addition probes plus the round-4 reviewer's own two reproduction edits) were executed, observed failing, and reverted clean — see the transcript section below.
- `ConcordClient.handleRemoved`'s prune now has a behavioral test driven through the real `onRemoved` wiring, proven non-vacuous by a recorded revert/RED/restore/GREEN cycle — see the transcript section below.
- WR4-02: the `held_roots` rule comment and `held-list`'s `checkKind` comment now state the actual `refounder`-stripping asymmetry; no disposition value changed.
