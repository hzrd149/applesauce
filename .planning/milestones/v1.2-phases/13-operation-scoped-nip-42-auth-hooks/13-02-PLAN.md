<objective>
Convert `req()` — and with it `request()` and `subscription()` — off the ambient pre-block and the
throw-as-signal retry, onto the shared auth operator from plan 13-01. This is the plan that actually
closes RAUTH-02: today a REQ that has never itself been rejected waits behind an unrelated earlier
REQ's auth-required.

Purpose: `req` is the highest-traffic auth site and the model the other three sites follow; getting its
pipe order and signal shape right (D-01, D-02, D-09) determines what the rest of the phase copies.
Output: a `req()` whose auth handling lives entirely in the shared operator, a `request()` whose 30s
clock is suspended across the auth phase (D-15), and a wire-trace test suite.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay -> client | the `CLOSED` reason string drives whether a REQ retries, waits, or errors |
| client app -> library | `onAuthRequired` runs arbitrary caller code inside the REQ pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Denial of Service | `req()` retry path | high | mitigate | Removing the pre-block means a relay answering `auth-required:` to every REQ drives repeated REQ frames; the shared operator's consecutive counter caps sends at `authRetries + 1` and each phase carries its own `authTimeout`. Task 3 pins this with an explicit frame-count assertion so a regression is caught at test time rather than in the field. |
| T-13-02 | Repudiation | `onAuthRequired` invocation in `req()` | medium | mitigate | A rejecting handler surfaces as `AuthHandlerError` scoped to that REQ only; Task 3's concurrency test proves a rejection on one operation leaves the sibling operation able to retry, so a handler bug cannot be mistaken for a relay-wide failure. |
| T-13-03 | Tampering | two concurrent REQs authenticating the same pubkey | low | accept | Both handlers run and may each drive an AUTH. Accepted per RAUTH-05 (no relay-internal dedupe); `Relay.auth()` re-keys by pubkey so the duplicate is idempotent at the state level. |
| T-13-SC | Tampering | package-manager installs | n/a | accept | Not applicable — no dependency is added by this plan. |
</threat_model>
