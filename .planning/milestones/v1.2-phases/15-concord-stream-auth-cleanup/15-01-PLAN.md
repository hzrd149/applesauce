<objective>
Build the scope-owned auth primitives every later plan in this phase wires up: a per-scope
`StreamSigners` holder whose `onAuthRequired` handler intersects the relay-supplied
`missingPubkeys` against the signers that scope holds (D-02/D-06/D-07), a separate client-wide
user-key handler factory (D-08/D-09), and the `connected$` derivation lifted out of the class
being deleted (D-12). Nothing is removed in this plan — it is purely additive, so the package
compiles and the whole suite stays green.

Purpose: this module is the single replacement for `ConcordRelayAuth`'s registry half. Every
subsequent plan (engines, publishes, invite watcher, examples) consumes it, so it lands first and
alone, with its own unit oracle proving the scoping property CAUTH-01 names before any call site
depends on it.

Output: `packages/concord/src/client/auth.ts`, its unit test, and a one-symbol widening of the
package's public export surface.
</objective>

Export `interface StreamSignersOptions` with one optional member,
`onAuthFailure?: (message: string) => void`. This is D-13's plumbing — the engine that owns the
holder passes a callback that records the message; the holder itself never touches any status
observable.

Export `class StreamSigners`:
- Private `registry = new Map<string, PrivateKeySigner>()`. Keys are x-only hex pubkeys. Per D-07
  this map accumulates within its scope — a historical epoch re-walk still needs old keys — and it
  is intentionally never pruned. Do not add eviction, size limits, or a shared/static map.
- `constructor(options: StreamSignersOptions = {})`, storing `onAuthFailure`. It takes NO
  `RelayPool` — this holder is a pure pubkey→signer map with no pool reference, no subscriptions,
  and no `challenge$`/`status$` awareness of any kind (D-01).
- `register(keys: GroupKey[]): string[]` — idempotent; skips a `pk` already present; constructs
  `new PrivateKeySigner(k.sk)` for each new one; returns the newly-added pubkeys. This is the
  same contract as the old `registerStreamKeys`, minus the version-bump side effect (there is no
  version counter — nothing observes registration any more).
- `addSecretKey(secretKey: Uint8Array): string` — registers a raw secp256k1 secret key that is
  NOT a `GroupKey` (it has no `convKey` and never addresses a plane): an invite-link signer key,
  freshly generated or restored from a stored `signerSk`. Derives the x-only hex pubkey the same
  way `groupKey` does (`bytesToHex(schnorr.getPublicKey(sk))`, or by awaiting the constructed
  `PrivateKeySigner`'s own public key if that keeps the method synchronous-free), registers it
  idempotently, and returns the pubkey. This method exists because D-17's invite-link publishes
  (`community.ts` invite mint / refresh / revoke and `invite-manager.ts`'s membership-free
  bundle revocation) sign with exactly such a key and a gating relay checks THAT author (D-16).
  Keep the method synchronous if the pubkey can be derived without awaiting; if not, return a
  `Promise<string>` and say so in the doc comment so call sites await it before publishing.
- `get(pubkey: string): PrivateKeySigner | undefined` — a plain map lookup. This is the only
  lookup shape the handler needs; do not add a whole-registry list accessor for the handler's use.
- `pubkeys(): string[]` — the held pubkeys, for tests and diagnostics only.
- `readonly onAuthRequired: RelayAuthHandler` declared as an ARROW-FUNCTION CLASS FIELD (not a
  method), so a call site can pass `holder.onAuthRequired` unbound directly into an options bag.
  Its body is D-02's whole mechanism and must not grow beyond it: iterate `missingPubkeys ?? []`;
  for each pubkey do `this.registry.get(pk)`; when there is no signer, `continue` — never throw,
  never fall back to another key, never fall back to the whole registry; when there is a signer,
  `await relay.authenticate(signer)` and read success off the resolved payload's `ok` field, NOT
  off a catch (`relay.authenticate` resolves `{ ok: false }` on a relay refusal — the same
  two-outcome shape `relay-auth.ts` lines 219-225 documents).
  Trace one line per attempt through `authLog` using the existing convention: the relay URL in
  full and the pubkey truncated with `.slice(0, 8)`.
  On `ok === false` call `this.fail(url, pk, "relay rejected the AUTH")`; on a caught throw call
  `this.fail(url, pk, message)` where `message` is `(err as Error)?.message ?? String(err)`.
  The handler itself must never reject — a failed AUTH is a value, not an exception (13-D-01/D-02).
- Private `fail(url: string, pubkey: string, reason: string)` — builds the D-13 message with this
  exact shape and calls `this.options.onAuthFailure?.(message)`:
  `auth failed on <url> for stream key <first 8 chars of pubkey>: <reason>`.
  Never interpolate a secret key, an invite token, or a full signer object into this message.

Export `function createUserAuthHandler(signer: ISigner, getPubkey: () => string | undefined, options: StreamSignersOptions = {}): RelayAuthHandler`.
This is D-08/D-09's separate path — the user's signer can be a NIP-46 bunker or an extension
dialog, so it stays off the stream code path entirely. Body: resolve `const pubkey = getPubkey()`;
if it is undefined, return without authenticating (the caller has not resolved the user yet).
Authenticate only when `missingPubkeys === null` (the operation asked for any authenticated user)
OR `missingPubkeys.includes(pubkey)`. Never authenticate for any other pubkey in the array — this
handler owns exactly one identity. Same `ok`-off-the-payload reading, same never-throw contract,
same failure message shape but with the words `for user` in place of `for stream key`.
The `getPubkey` thunk (rather than a bare string) exists because `InviteWatcher` resolves the
user's pubkey asynchronously in `start()` while `ConcordClient` has it earlier — one shape serves
both.

Export `function lookupRelayStatus(statuses: Record<string, RelayStatus>, url: string): RelayStatus | undefined`
returning `statuses[normalizeURL(url)] ?? statuses[url]` — the un/normalized-URL tolerance lifted
verbatim from `relay-auth.ts:76-78`.

Export `function connectedRelays$(pool: RelayPool, relays: string[]): Observable<boolean>` —
the D-12 extraction, settling that discretion item in favour of ONE shared free function rather
than a per-engine copy. Body is `relay-auth.ts:85-91` with `this.lookupStatus` replaced by the
free function: pipe `pool.status$` through `startWith({})`, `map` to
`relays.some((url) => lookupRelayStatus(statuses, url)?.connected ?? false)`, then
`distinctUntilChanged()`. It reads only `status.connected` — it must not read
`authRequiredForRead`, `authRequiredForPublish`, `authenticatedPubkeys`, or `challenge`
(RESEARCH.md Pitfall 2: those are relay-wide, not operation-scoped).

Do NOT port any of: a version counter, a per-relay driver, reference counting, a `challenge$`
subscription, a `status$` subscription that triggers an AUTH, an in-flight/dedupe guard (D-18
declines dedupe deliberately at every layer), or a satisfied-when-no-flags-set gate (D-11).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concord engine → relay socket | A NIP-42 AUTH event signed by a stream secret key or the user's signer crosses to an untrusted relay. |
| relay → `onAuthRequired` handler | `missingPubkeys`, `reason`, and `url` are relay-influenced values entering concord's handler. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-01 | Spoofing | `StreamSigners.onAuthRequired` | high | mitigate | Look up each pubkey with `this.registry.get(pk)` on the instance's OWN map and `continue` when absent. No cross-instance map, no static/shared registry, no fallback branch. Proven by the disjoint-scopes and unheld-pubkey tests. |
| T-15-02 | Information disclosure | `fail()` message + `authLog` lines | medium | mitigate | Messages carry the relay URL and an 8-character pubkey prefix only. No secret key, invite token, or signer object is ever interpolated — mirrors the existing "NEVER log `link.token`" rule in `community.ts`. |
| T-15-03 | Spoofing / elevation | `createUserAuthHandler` | high | mitigate | Authenticate only when `missingPubkeys` is `null` or contains the thunk-resolved user pubkey; never iterate the array and authenticate arbitrary entries. Proven by the excluded-pubkey test. |
| T-15-04 | Tampering (concurrency) | concurrent AUTH for one key | low | accept | D-18: a duplicate AUTH is one extra local signature and one extra frame for in-memory keys. Ruled on by the user; no dedupe at any layer. |
| T-15-05 | Denial of service (memory) | unbounded registry growth | low | accept | D-07: keys accumulate within a scope by design so a historical epoch re-walk still resolves. Explicitly ruled out of scope by the user; no eviction is to be added. |

No package-manager installs occur in this phase (RESEARCH.md § Standard Stack), so no
supply-chain threat row and no package-legitimacy checkpoint applies.
</threat_model>
