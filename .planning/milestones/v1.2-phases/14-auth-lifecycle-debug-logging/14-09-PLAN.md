# Plan 14-09: Finish the ALOG-03 derive-once sweep and widen the guard that missed it

## Objective

Close code-review finding **WR-07**. Plan 14-02 hoisted `buildRelayStream`'s `requestLog` out of its
`switchMap` projector and added a regression test — but `paginatedRequest` (`sync-loader.ts:248`)
still derives two `Debugger`s per call from the same re-enterable path, and the guard 14-02 added
counts only the `"request"` namespace segment, so it is structurally unable to see them.

This matters beyond the one call site: ALOG-03 is the requirement 14-02 *restated* specifically so it
could be honestly verified. Right now the restated criterion is still not true for the package, and
the guard that is supposed to prove it has a blind spot in exactly the shape of the surviving
violation. Read `.planning/phases/14-auth-lifecycle-debug-logging/14-REVIEW.md`, finding **WR-07**
(line 306), for the exact locations and analysis.

## Tasks

### Task 1 — Hoist the surviving derivations in `paginatedRequest`

Derive both loggers once per invocation, outside any scope a reactive pipeline can re-enter, matching
the pattern 14-02 established in `buildRelayStream`. Read what 14-02 actually did first
(`.planning/phases/14-auth-lifecycle-debug-logging/14-02-SUMMARY.md`) and follow that shape rather
than inventing a second convention.

Commit atomically.

### Task 2 — Widen the guard so it could have caught this

Extend the regression test so it observes derivation across the namespace segments the package
actually uses, not just `"request"`. The test must fail against `paginatedRequest` as it stands
before Task 1 and pass after.

Prove that ordering explicitly: revert Task 1's hoist with the Edit tool, confirm the widened guard
fails, restore, confirm it passes. Record the exact failure output in the SUMMARY — a guard that has
never been seen to fail is not a guard.

Commit atomically.
