<objective>
Make `event()`'s locally-manufactured publish timeout mark itself structurally, and bring the pending
`applesauce-relay` changeset set in line with everything this phase changed.

Purpose: today the manufactured timeout and a relay rejection are byte-identical response objects, so
neither the log nor the auth state can tell a client giving up from a relay saying no — the exact defect
class recorded three times across Phase 13, a call site's own bookkeeping value consumed as real by a
shared consumer (D-11). And because the whole Phase 13 auth surface is unreleased (D-01), the changeset
that will become the published changelog still advertises a context field this phase removed.

Output: the error discriminator set on one branch, a regression test proving both halves, an edited
changeset body, and three new single-sentence changesets.
</objective>

Assert absence explicitly (the property is undefined or not present), not merely that the value is falsy.

2. **Local timeout** — publish an event against a relay configured with a short `eventTimeout` and have the mock relay never reply. Assert the resolved response reports failure and carries an `error` field holding a real `Error`. Derive the expectation from the scenario — no `OK` frame was ever sent, so the response cannot have come from the relay — rather than from the implementation's construction.

This is the half D-11 actually cares about: the defect was that a shared consumer could not tell the two apart, and this test proves the fix reaches that consumer.

Do not add a test that asserts on the timeout response's message string as the discriminator — that would encode the very anti-pattern being removed.
