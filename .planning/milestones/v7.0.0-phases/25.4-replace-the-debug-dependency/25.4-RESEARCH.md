# Phase 25.4: Replace the debug Dependency — Research

**Researched:** 2026-09-06
**Requirement:** DEBUG-01
**Confidence:** HIGH

## Recommendation

Implement the workspace's observed logging contract in `packages/core/src/logger.ts` and export its `Debugger` type plus narrowly named test-control functions from `applesauce-core`. Do not add a replacement dependency and do not reproduce `debug` features absent from current call sites.

## Actual Compatibility Surface

Production call sites use a callable `Debugger`, `.extend(segment)`, and `.namespace`. Logger enablement must remain dynamic after construction because module-scope loggers are created before tests or consumers enable namespaces. Existing output requires Node/browser-safe printf handling compatible with `%s`, `%d`, `%o`, `%O`, `%j`, and `%%`, with extra arguments preserved. Namespace matching must support comma/space-separated positive and `-` negative patterns, `*` wildcards spanning `:` segments, and the conventional `DEBUG` environment or browser-storage seed when available.

## Risks and Mitigations

- Module-scope loggers can cache a false enable state: compute enablement at each call or update all created instances when patterns change; prove late enablement.
- Formatting drift can invalidate security-sensitive auth log tests: assert hostile `%` and newline values through the actual sink, not a parallel renderer alone.
- Browser bundles can break on `node:util`: implement the small observed formatter without importing Node built-ins in production code.
- Declaration builds can retain `debug` transitively: negative-scan emitted declarations and source imports after all package builds.

## Package Legitimacy Audit

No npm, pip, or cargo package is added. The replacement is repository-owned code and existing dependencies are removed.
